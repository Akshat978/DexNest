# Projects - plan

Module id `projects` · table prefix `proj_` · event namespace `projects.` ·
event stream `projects` · view id `dev` (kept, see 16) · packages
`@dexnest/projects` and `@dexnest/git-ops` · host
`apps/desktop/src/main/projectsHost.ts` · branch `cloud/projects`.

Status: **Phase 1 (contracts) done.** Owner accepted every default in 18. Read with `AGENTS.md`,
`docs/DEXNEST_FOUNDATION_ARCHITECTURE.md` and `docs/ui-audit/REPORT.md` (on
`cloud/ui-audit`). Shaped after Developer Intelligence's runtime/host split
and the modules built before it (ObjectOS, GhostOS, Reality RPG, Skill
Constellation).

---

## 1. What it is

One place for every code project: each project, its branches locally and on
GitHub, how far each branch is from this PC, and one-click, previewed, logged
git operations, VS Code, terminal and run commands. It **evolves the existing
Dev dashboard** - same sidebar entry, same view, same action ids - rather than
adding a parallel module.

## 2. Scope (this build)

- Projects in `proj_` tables, migrated once from `settings/projects.json`.
- Groups, tags, favourites, pinned, archive (instead of delete), sort by
  last activity.
- Add-project wizard (folder dialog / drag-drop / paste path), inspector that
  pre-fills everything, Developer Intelligence suggestions, clone from a URL.
- A read-only git engine (branches, comparisons, worktrees, stashes, states).
- `git-ops`: every git operation that changes anything, with preflight,
  plain-words preview, journal, undo where possible, and hard refusals.
- Open in VS Code / terminal / file explorer / GitHub page.
- Every existing Run feature (commands, stop, restart, ports, health, logs,
  docker) in the project's Run tab.
- Registered actions, `projects.*` events, host, IPC, preload, the view.

## 3. Out of scope

- **GitHub API** (pull requests, CI status, issues): no call to
  `api.github.com` or `gh`. A hook only: `RemoteHostingPort` in
  `packages/projects/src/domain/hosting.ts` (`describePullRequests(project,
  branch)` etc.), with no implementation, documented as "later, opt-in, via
  the locally logged-in `gh` CLI, through `git-ops`-style allowlisted argv".
  The UI reserves a slot (Branches table column "PR", hidden).
- Diff viewer of file contents; merge-conflict resolution UI (conflicted files
  are listed, with "open in VS Code").
- Writing to Developer Intelligence in any way.
- Mobile, phone exposure of any projects action.
- `modules/dev/src/index.tsx`: an unused placeholder (no importer). Left
  untouched; noted for removal in a later cleanup, not by this module.

## 8. Migrating `projects.json`

1. On host start, if `proj_meta.legacy_import` is absent and
   `settings/projects.json` exists: parse it (same tolerance as
   `readJsonFile`: corrupt -> left alone, reported, nothing imported).
2. Map every entry with `legacyProjectToRows` (pure, domain): every field to
   its column/table; `legacy_json` = the entry verbatim; ids preserved.
3. One transaction: insert all, write `proj_meta.legacy_import` = {sha256,
   count, imported_at, backup}.
4. Copy the file to `settings/backups/projects.json.<ts>.bak` (copy, then
   verify hash). The original is left in place but **no longer read**.
5. Idempotent: a second start finds `legacy_import` and does nothing. If
   `projects.json` later changes (hash differs), the view shows "projects.json
   changed since import - Import differences?" and never merges by itself.
6. Export the other way: `exportLegacyProjects()` returns the old
   `DexNestProject[]` shape from the DB. `loadProjects()` in `main.ts` becomes
   a one-line call to it, so F25-F33 keep working unchanged.

Tests (Phase 2): synthetic files in temp dirs only - every field round-trips;
unknown fields survive; corrupt file; empty array; duplicate ids; second run
is a no-op; close/reopen; backup exists with the same hash.

## 9. Git: what is read (packages/projects, read-only)

Runner env: `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `LC_ALL=C`,
`-c core.fsmonitor=false`; argv only; timeout 15 s per call; output caps.
**Allowlist** (verb + required shape), not a denylist: `rev-parse`,
`status --porcelain=v2 --branch`, `for-each-ref`, `rev-list --count` /
`--left-right --count`, `log`, `stash list`, `worktree list --porcelain`,
`remote get-url`, `merge-base --is-ancestor`, `diff --numstat` /
`--name-status` (stats only, never content), `ls-files --unmerged`. Anything
else throws before spawning.

Per project (`RepoState`): current branch or detached HEAD, staged /
unstaged / untracked / conflicted counts and paths (capped), ahead/behind
upstream, stashes, last commit (sha, subject, date), operation in progress
(merge, rebase, cherry-pick, revert, bisect - from `.git` files), worktrees
(main, Autopilot's, other), submodules (listed, not recursed), last fetch
time.

Per branch (`BranchRow`, one `for-each-ref` over `refs/heads refs/remotes`
plus `rev-list --left-right --count` per pair, batched): ahead/behind vs
upstream, ahead/behind vs default branch, last commit date and subject,
local-only / remote-only / upstream gone, merged into default
(`merge-base --is-ancestor`), stale (no commit for `staleDays`, default 30),
checked out in another worktree (and whose).

Project badge (one, by priority): `conflict` > `operation in progress` >
`diverged` > `N to pull` > `N to push` > `uncommitted changes` > `all pushed`
(+ "no upstream" / "not a git repo"). Always shown with "fetched N minutes
ago" or "never fetched".

Large repos: per-branch comparisons limited to the 50 most recent branches,
"show all" loads the rest; every count call shares one cancel handle.

## 10. Git: what can be done (packages/git-ops)

Every operation is `preflight(state) -> OperationPlan | Refusal` (pure, in
`projects/domain`, Phase 1) then `execute(plan)` (git-ops, Phase 4):

```
read fresh state -> plan (refusal or preview) -> owner confirms per class
-> journal "running" + event projects.op.started (refs before)
-> run argv -> read state again -> verify expected result
-> journal "succeeded"/"failed" + event projects.op.finished (refs after, undo)
```

| Class | Operations | UI |
|---|---|---|
| **normal** | fetch, fetch all, pull (`--ff-only`), push, push and set upstream (new branch), commit (message required; all or chosen files), stash, stash pop (clean), switch branch (dirty -> "stash them, or cancel"), create branch | preview + one click |
| **caution** | delete a merged local branch; discard changes in chosen files (backup stash first); pop a stash that would conflict | confirmation dialog |
| **strong** | delete an unmerged local branch; delete a remote branch | type the branch name |
| **never** | force push (any `-f`, `--force*`, `+refspec`, `--mirror`), `reset --hard`, `clean`, `rebase`, `filter-branch`, `filter-repo`, `commit --amend` of a pushed commit, `update-ref -d`, `reflog expire`, `gc --prune=now`, `push --delete` without strong confirmation, `checkout -- .`, anything rewriting pushed history | not offered; the argv validator throws |

Refusals in plain words, e.g. pull: "main has 2 local commits and origin/main
has 3 new ones - they have diverged. DexNest won't merge or rebase for you;
open a terminal here." Push: refuses when behind or diverged; offers "push and
set upstream" when there is no upstream; never touches a branch checked out
in another worktree.

**Undo** (refs recorded before every operation):
- commit -> `reset --soft <parent>` only if HEAD is still that commit and no
  remote-tracking ref contains it;
- branch delete -> `branch <name> <recorded sha>`;
- discard -> discard *is* `stash push -m "dexnest-discard-<opId>" -- <paths>`,
  undo is `stash apply <recorded stash sha>` (found by sha, not index);
- switch -> switch back; create branch -> delete it if still at its start.

**Runner** (`git-ops`): argv only, `shell: false`; verbs allowlisted; NEVER
tokens rejected wherever they appear; env `GIT_TERMINAL_PROMPT=0`,
`GCM_INTERACTIVE=never`, `GIT_ASKPASS=` (empty), `SSH_ASKPASS=` ,
`GIT_ALLOW_PROTOCOL=https:ssh:git:file`, `-c protocol.ext.allow=never`; ssh
gets `-o BatchMode=yes` only when the owner has not set `core.sshCommand`
(open question 6); timeouts (fetch/pull/push/clone 5 min, local 60 s) and
cancel. Stderr matching "Authentication failed", "could not read Username",
"Permission denied (publickey)", "terminal prompts disabled" -> outcome
`auth_needed` -> "Authentication needed - open a terminal here" with a
button that opens the terminal in the project folder.

**Concurrency:** one operation per project at a time (in-memory lock + a
`running` row); a second request gets "busy - <verb> is running". Bulk ops run
projects sequentially (fetch all: 4 at a time). On start, `running` rows
become `interrupted` and the view shows what may need checking (and
`index.lock` if git left one - reported, never deleted by DexNest).

**Bulk:** fetch all; pull all = only clean projects that can fast-forward,
the rest reported with the reason; no bulk push.

Tokens are stripped from remote URLs (`https://user:tok@host/...` ->
`https://host/...`) in everything shown, logged, journalled or stored.

## 11. Adding projects

```
Pick folder (dialog) | drop folder on window | paste path
   -> boundary check (written + realpath)  -> refuse if inside data root
   -> duplicate check (same real path, or same normalised remote) -> "Open existing"
   -> inspector: name (package.json name or folder), git?, remote + GitHub
      owner/repo, default branch (origin/HEAD, else main/master), package
      manager (lockfile), scripts -> suggested commands, framework (deps),
      *.code-workspace, likely ports (scripts --port, vite config, .env.example)
   -> pre-filled form -> Save
```

Suggestions: DI's discovered repositories whose real path is not a project
(and not archived, not inside the data root); add one, or select several and
"Add all" (each still inspected; one summary). Clone: paste URL (https or
`git@host:owner/repo`), pick a parent folder, preview "Clone owner/repo into
D:\code\repo", run (network, only on click), then the wizard opens on it.
Editing uses the same form, pre-filled from the project.

## 12. Open and run

- VS Code: `code` on PATH, else `%LOCALAPPDATA%\Programs\Microsoft VS Code`,
  `%ProgramFiles%\Microsoft VS Code` (prefer `Code.exe` over `code.cmd` - a
  `.cmd` cannot be spawned without a shell on current Node); not found ->
  say so with "Locate VS Code..." (stored in settings). Open the
  `.code-workspace` when the project has one.
- Terminal: Windows Terminal (`wt.exe -d <path>`) if present, else the existing
  PowerShell launch (F10). Setting to choose.
- File explorer: `shell.openPath` (F8).
- GitHub page of the repo, a branch, or `compare/<default>...<branch>`:
  built from the parsed remote, opened with `shell.openExternal` (only
  `https://github.com/...`).
- Run tab: F13-F24 unchanged in behaviour; their code moves from `main.ts`
  into `projectsHost.ts` (`projectsRun.ts` helper) behind the same action ids.

## 17. Risks

| Risk | Mitigation |
|---|---|
| A bug loses a project during migration | verbatim `legacy_json`, backup copy with hash check, original file left in place, idempotent, synthetic-file tests |
| A mutating git command reached from the read path | separate package, dependency-direction test, read allowlist, static scan for verbs (DI's EC-037 pattern) |
| A NEVER operation slips through via an option or refspec | token-level validator over the whole argv (`+refs`, `--force*`, `-f`, `--hard`, `--mirror`...), refusal test per rule, mutation checks |
| Git prompts and hangs (credentials, editor, pager) | `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, `GIT_EDITOR=true` never needed (`-m` always), `--no-edit`, `GIT_PAGER=cat`, timeouts, cancel |
| Git hooks run user code (pre-commit, pre-push) | expected git behaviour; shown in the preview ("this repo has a pre-commit hook"); timeouts |
| Malicious repo config (`core.fsmonitor`, `core.sshCommand`) on a suggested repo | reads pass `-c core.fsmonitor=false`; projects are only repos the owner adds |
| Network on startup | no fetch unless clicked or scheduled (off); a test asserts no network verb runs at host start |
| Two operations race in one repo | per-project lock + journal; git's own `index.lock` reported |
| Touching Autopilot's worktree branch | worktree list read before every plan; refusal |
| `main.ts` merge conflicts with other branches | delegating one-liners only; host file holds the logic |
| Tokens in remote URLs leaking into logs/events | `stripUrlCredentials` everywhere + bait test with a fake token |
| Windows specifics untestable here | "needs Windows check" list (GCM, `code`/`Code.exe`, `wt.exe`, PowerShell, junctions, `\\?\` long paths, CRLF, case) |
| UI kit work grows | only the components Projects uses; existing views untouched |

### Refinements made in Phase 1

- **Steps are data, not argv.** A plan holds structured `GitStep`s
  (`{op: "push", remote, branch, setUpstream}` ...). `@dexnest/projects`
  never spells a mutating git command line (static test); git-ops turns
  steps into argv in Phase 4 and checks them again.
- **A leading `+` is refused in branch names** (found while writing the
  tests): on a push command line `+main` is a force-push refspec. Git itself
  allows such names, so an existing `+x` branch is simply never pushed,
  switched or deleted by DexNest.
- **Requests are parsed strictly.** `parseOperationRequest` refuses NEVER
  operations by name (`force_push`, `reset_hard`, `clean`, `rebase`,
  `amend`...), NEVER flags on any allowed operation (`force`,
  `forceWithLease`, `mirror`, `hard`, `rebase`, `amend`...), and any unknown
  field, rather than ignoring it.
- **Discard is a stash.** The plan's only step is
  `stash push -- <paths>` (with `-u` when new files are included); undo
  applies that stash by sha. There is no checkout/restore/clean step anywhere.
- **Pull is planned even when the last fetch says "nothing to pull"** (the
  fetch may be stale and pull fetches first); diverged is refused. Push
  refuses on the cached counts (behind, diverged, nothing to push); git
  rejects a non-fast-forward push on its own if the remote moved since.
- **Stash pop** always applies then drops only if clean, so a conflicting
  pop keeps the stash. When the stash's files overlap current changes (or are
  unknown while the tree is dirty) the plan is caution class.
- **Undo** needs facts the state doesn't carry (`commitOnRemote`,
  `objectExists`); the read engine supplies them (Phase 3). Undo of a commit
  is refused unless the engine can say the commit is on no remote-tracking
  ref. The first commit of a repository has no undo.
- **Delete branch** is caution when merged into the default branch, strong
  (type the name) otherwise or when that is unknown. The default branch and
  the current branch are never deleted; nor a remote default branch.
- **Pull all** takes only clean projects that are behind and not ahead.
- **Triggers**: `PROJECTS_ACTIONS` is the contract the registry entries
  will be generated from; `deckSafe` is tested over the whole list and
  `triggerAllowed` is what the runtime will enforce.
- **Remote URLs**: `stripUrlCredentials` drops any userinfo from http(s)
  and any password from ssh; `redactCredentials` also removes GitHub token
  shapes (`ghp_...`, `github_pat_...`) from free text such as stderr.
